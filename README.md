# Сайт ООО «СитиСтрой» (Казань)

Сайт строительной компании: гражданское и промышленное строительство, генеральный подряд,
поставки цемента. Живёт на **Vercel**.

## Что где лежит

| Папка | Что это |
|---|---|
| `site/` | **Готовый сайт.** Это и есть проект, который деплоится на Vercel |
| `site/api/send.js` | Приём заявок с формы — serverless-функция Vercel (Node.js) |
| `site/mail/` | Старый вариант приёма заявок на PHP — на Vercel не используется, оставлен на случай переезда на обычный хостинг (см. ниже) |
| `_build/` | Исходники, из которых собираются страницы `site/*.html` |

## Настройка проекта на Vercel

При первом подключении репозитория нужно один раз задать в панели Vercel:

1. **Settings → General → Root Directory** — указать `site`.
   Сайт лежит не в корне репозитория, а в подпапке — без этой настройки Vercel
   не находит `index.html` и показывает 404.
2. **Settings → Environment Variables** — добавить переменные для отправки почты
   (см. раздел «Заявки с сайта» ниже).

После изменения Root Directory или переменных окружения нужен **Redeploy**
(Deployments → последний деплой → ⋯ → Redeploy), просто push это не подхватывает
на уже созданном проекте.

## Как вносить правки

Страницы в `site/*.html` собираются автоматически — **править их напрямую нельзя**,
изменения затрутся при следующей сборке. Редактировать нужно исходники в `_build/`:

* `_build/shell.html` — общий каркас: шапка, мобильное меню, футер;
* `_build/pages/*.html` — содержимое конкретных страниц;
* `_build/parts/*.html` — повторяющиеся блоки (форма заявки, карточки объектов, галереи).

После правок запустить сборку — она пересоберёт все 15 страниц:

```
powershell -File _build/build.ps1
```

Стили (`site/assets/css/style.css`) и скрипты (`site/assets/js/main.js`) правятся напрямую.
Дальше — обычные `git add`, `git commit`, `git push`: Vercel передеплоит сайт сам.

## Заявки с сайта

Форма отправляет данные на `/api/send` — это `site/api/send.js`, функция на Node.js
(библиотека `nodemailer`). Все настройки задаются переменными окружения в панели Vercel
(**Settings → Environment Variables**), в коде их нет:

| Переменная | Обязательна | Что это |
|---|---|---|
| `SMTP_HOST` | да | адрес почтового сервера, например `smtp.yandex.ru` |
| `SMTP_USER` | да | полный адрес ящика-отправителя |
| `SMTP_PASS` | да | **пароль приложения** (не обычный пароль от почты) |
| `SMTP_PORT` | нет | `465` по умолчанию (`587` — для TLS) |
| `SMTP_SECURE` | нет | `ssl` по умолчанию (для порта 587 указать `tls`) |
| `TO_EMAIL` | нет | куда приходят заявки, по умолчанию `ascetovu@gmail.com` |
| `FROM_NAME` | нет | имя отправителя в письме |

Пока `SMTP_HOST` / `SMTP_USER` / `SMTP_PASS` не заданы, форма честно отвечает
«Почта на сайте ещё не настроена», а сама заявка попадает в логи функции
(Vercel → проект → вкладка **Logs**) — так минимум видно, что клиент писал.

### Как получить пароль приложения

* **Яндекс.Почта** — id.yandex.ru → «Безопасность» → «Пароли приложений» → «Почта».
  В настройках почты дополнительно включить «Портальный доступ по протоколу SMTP».
* **Mail.ru** — «Настройки» → «Безопасность» → «Пароли для внешних приложений».
* **Gmail** — myaccount.google.com → «Безопасность» → «Пароли приложений»
  (нужна включённая двухэтапная аутентификация).

### Если решите вернуться на обычный PHP-хостинг

В `site/mail/` лежит рабочий PHP-вариант той же формы (PHPMailer, тот же набор проверок).
Тогда в `site/assets/js/main.js` нужно вернуть адрес формы с `/api/send` на `mail/send.php`,
а настройки почты вписать в `site/mail/config.php` — там тоже есть инструкция.

> Репозиторий публичный — реальный пароль от почты не должен попасть ни в `config.php`,
> ни в код. На Vercel он и так безопасно хранится в Environment Variables.

## Требования

Для serverless-функции — Node.js 20 (задано в `site/package.json`, Vercel подхватывает сам).
Для страницы «Контакты» используется виджет Яндекс.Карт — ключ API не нужен.
